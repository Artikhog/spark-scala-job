# RDD и DataFrame в Apache Spark

## Исходные данные

Использован [OpenCitations HTTP access logs, January–April 2026, версия 1.0.0](https://zenodo.org/records/20289873).
Одна CSV-запись описывает HTTP-запрос. В поле `hashed_ip` хранится SHA-1 от IP
клиента, поэтому группировка выполняется по обезличенному идентификатору адреса.
Другие поля содержат страну, HTTP-метод, путь запроса, код ответа, user agent
и время события. Для выбранной агрегации требуется только `hashed_ip`.

Из январского файла oc-2026-01.csv подготовлены три фрагмента на 1, 2 и 4 Гб
Для подготовки набора данных можно запустить скрипт scripts/prepare_data.py

## Задача 

Для каждого hashed_ip подсчитать количество HTTP-запросов.
Каждая исходная запись с непустым ключом вносит единицу в счётчик своей группы.
Учитываются все HTTP-статусы и методы запросов. null и пустая строка в ключе
исключаются

Выход обеих реализаций — пары (hashed_ip, count), где count - число запросов.
Cравниваются ключи и соответствующие им значения счётчиков

## Запуск Spark local задачи

Задачи запускаются с помощью системы сборки sbt. Внутри приложения создается Spark сессия и в ней запускаются RDD и Dataframe преобразования. После выполнения результаты сохраняются в подкаталоги rdd и dataframe и в finally блоке освобождаются ресурсы

## Реализация через RDD

Код с RDD лежит в файле src/main/scala/RddIpEventCount.scala

Файл читается построчно, для чтения партиции используется CsvParser, первая строка с заголовком отбрасывается, из строки выделяется ip запроса. Далее 
- filter удаляет строки с пустыми ключами
- map каждому ip ставит в пару единицу 
- reduceByKey суммирует по ключу

При выполнении задачи разбор строк, фильтрация и создание пары выполняется внутри разделов reduceByKey, предварительно ключи в одном разделе суммируются и на shuffle частичные суммы полностью объединяются

### Transformations и actions

Для RDD задачи tranformations будут:
- .mapPartitionsWithIndex()
- .filter()
- .map()
- .reduceByKey()
- rddCounts.values
- fullOuterJoin()
- filter
А actions будут:
- rddCounts.count()
- .fold()
- .count()

## Реализация через Dataframe

Код с DataFrame лежит в файле src/main/scala/DataFrameIpEventCount.scala

Сначала в коде задается схема колонок для Dataframe и настраиваются параметры источника, после этого выполняется цепочка 

```scala
.csv(input)
.select(col("hashed_ip"))
.filter(col("hashed_ip").isNotNull && length(col("hashed_ip")) > 0)
.groupBy("hashed_ip")
.count()
```

Выбирается нужный столбец, фильтруются пустые значения, записи группируются по ip и суммируются 
В файле dataframe-explain.txt записан результат explain, по физическому плану сначала идет предварительный расчет внутри разделов, shuffle и объединение результатов

### Transformations и actions

Для Dataframe задачи tranformations будут:
- .select(col("hashed_ip"))
- .filter()
- .count()
- dfCounts.agg()
- .orderBy()
А actions будут:
- .first()
- .write() для записи результата
- .show()

## Сравнение RDD и DataFrame

RDD предоставляет низкоуровневый api для работы с распределенной коллекцией Scala объектов, где при обработке можно задать любой код обработки
DataFrame более высокоуровневый и инструмент для работы с данными как с таблицей

Оба api поддерживают распределенную обработку, ленивые вычисления и требуют группировки одинаковых ключей между разделами. При этом Dataframe имеет оптимизатор вычислений. В обеих реализациях преобразования ленивые, вычисления запускаются actions

RDD и DataFrame дали одинаковые результаты на фрагментах 1, 2 и 4 ГБ, число различающихся ключей равно нулю
